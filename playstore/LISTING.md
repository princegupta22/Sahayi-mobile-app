## 2. In-app products (Monetize → Products → In-app products)

Create both as **one-time products**, status Active. Product IDs must match exactly (they are in the code).

| Product ID | Name | Description | Price |
|---|---|---|---|
| `contact_unlock` | Contact unlock | One-time payment to call and message any worker on Sahayi. | ₹149 |
| `worker_listing` | Worker profile | One-time payment to publish your worker profile on Sahayi. | ₹149 |

Do **not** make them subscriptions. The app consumes the purchase after unlocking the account, so the same Google account can buy again for another Sahayi account.

## 3. App content

### App access
Some features need an account and a purchase. Select **"All or some functionality is restricted"** and give reviewers:
- A demo account: email + password (create one in the app first, e.g. `reviewer@…`).
- Note: *"Sign up with email, no verification needed. Calling/messaging and publishing a worker profile need a one-time in-app purchase; please use a licensed test account (add the reviewer's Gmail under Setup → License testing)."*

### Ads
**No**, the app does not contain ads.

### Target audience and content
- Target age: **18 and over** only.
- Not designed for children. Appeals to children: No.

### Content rating (IARC questionnaire)
- Category: **Utility, Productivity, Communication or other**
- Violence / sexual content / profanity / drugs / gambling: **No**
- Does the app let users interact or exchange content (chat)? **Yes** (in-app chat between users)
- Does it share the user's location with others? **No**
- Does it allow users to purchase digital goods? **Yes**
- Expected rating: **Everyone / PEGI 3 – may show "Users interact"**

### News app / COVID / Government / Financial features / Health
All **No**.

### Data safety form

Does the app collect or share user data? **Yes collects. Shares: No** (Supabase and Google Play act as service providers on our behalf; this is not "sharing" under Google's definition).
Is all data encrypted in transit? **Yes**
Can users request data deletion? **Yes**, deletion URL: *(your published `delete-account.html` link)*

| Data type | Collected | Shared | Required / Optional | Purpose |
|---|---|---|---|---|
| Name | Yes | No | Required | App functionality, Account management |
| Email address | Yes | No | Required | App functionality, Account management |
| User IDs | Yes | No | Required | App functionality, Account management |
| Phone number | Yes | No | **Optional** (workers only) | App functionality |
| Address / city | Yes (city typed in worker profile, no device location) | No | Required for workers | App functionality |
| Photos | Yes | No | Optional | App functionality |
| Messages (in-app messages) | Yes | No | Optional | App functionality |
| Purchase history | Yes | No | Required to unlock | App functionality, Account management |
| Other info (service, experience, description) | Yes | No | Required for workers | App functionality |

Not collected: precise/approximate device location, contacts, call logs, SMS, files, audio, video, health, web history, device ID, crash logs, diagnostics.
For "Photos": mark **Photos** only (not "Videos"). Data is **not** processed ephemerally.

### Permissions declarations
The manifest currently declares `READ_MEDIA_IMAGES` and `READ_EXTERNAL_STORAGE` (≤ Android 12). Google restricts photo/video permissions; Play may ask you to justify them or reject. The app only needs the **system photo picker** (no permission), so the safest fix is to **remove both lines** from `android/app/src/main/AndroidManifest.xml` before uploading. If you keep them, answer the declaration with: *"Users pick a profile photo and up to 3 work photos."*

### Financial features, Health, etc.
None.

### Government apps / Advertising ID
Advertising ID: **No** (the app does not use it).

## 4. Account deletion (important)

Because users can create an account in the app, Google requires **(a)** a web page explaining deletion (`delete-account.html`, ready) **and** (b) a way to start deletion **inside the app**. The app does not have an in-app delete button yet; Play may flag this. Ask Claude to add "Delete my account" (Profile → Settings, with a confirm dialog and a server function that removes the account, listing, photos and chats) before the production release.

## 5. Pre-launch checklist

1. Run `supabase/worker_options.sql` and `supabase/play_billing.sql`, deploy `verify-play-purchase`, set the `GOOGLE_PLAY_SERVICE_ACCOUNT` secret.
2. Create the two in-app products above and activate them.
3. Upload `app-release.aab` to **Internal testing** first; test a purchase with a license-tester Gmail.
4. Fill App content (all sections above), then Store listing with the images in this folder.
5. Increase `version:` in `pubspec.yaml` (`1.0.0+2`, `+3`…) for every new upload.
6. Back up `android/app/upload-keystore.jks` and its password.
